# 异常处理指南

> 适用项目：AI 求职信息智能筛选助手
> 适用范围：全部业务模块（当前已实现：模块一 群监听配置、模块二 多模态消息解析、模块三 用户简历&求职意向配置、模块四 AI 岗位结构化抽取、模块五 岗位匹配打分、模块六 本地数据归档与日报）
> 文档索引：返回 [README.md](../README.md) 文档索引 ｜ 配套规范：[错误码体系.md](错误码体系.md)、[日志规范.md](日志规范.md)

## 一、异常分类：可重试 / 不可重试

### 可重试异常

- 网络抖动、NapCat 连接失败 / 断线
- 图片下载失败、网页抓取失败（连接超时、HTTP 错误）
- LLM 调用失败（网络/超时/HTTP 非 2xx/响应结构非法，`LLMCallError` PAR.LLM.001，模块四/五共用）
- 处理策略：监听器按 `reconnect_interval` 自动重连；多模态分支由编排层捕获后标记失败，**跳过该条、不中断整体流程**（对应 `MultimodalResult.errors`）；LLM 调用失败由 `JobExtractor.parse` / `JobScorer.score` 捕获后写入 `ParseResult.error` / `MatchResult.error`，**跳过该条消息/岗位、不中断整体流程**

### 不可重试异常

- 配置错误（文件缺失、YAML 语法错误、群号非法、ws_url 非法、简历/意向类型非法、llm 段类型非法、recommend_score_threshold 非法）
- 参数非法、业务规则校验失败（如重复启动监听器）
- OCR 依赖缺失（PaddleOCR 未安装）、页面/图片超过大小上限（资源保护）、OCR 识别超时（`ocr_timeout` 上限）
- 岗位 JSON 归档失败、日报写入失败（`JobSaveError` STO.SAVE.001 / `ReportError` STO.REPORT.001）：磁盘不可写、磁盘满等，由 `JobRepository.save_job` 标记返回 / main 记录 ERROR 后降级，不视为全局故障
- LLM 响应内容格式非法（模块四 `LLMFormatError` PAR.LLM.002 / 模块五 `ScoreFormatError` MAT.SCORE.001）：各自**自动重试一次**（`max_retries`），仍失败标记该条，不视为全局故障
- 处理策略：抛出带错误码的自定义异常，程序按错误类型处理（配置错误直接退出并提示修正；OCR 依赖缺失提示安装或关闭开关；超限/超时跳过该条；归档/日报写盘失败标记或降级）

### 策略性跳过（非异常）

- 需登录页面、JS 强渲染页面：命中特征后**显式识别并跳过**，不抓取正文（产品方案 3.2 控制策略），记录 INFO 日志原因，不进 `errors` 列表
- 非招聘相关消息（闲聊广告/诈骗/其他）：分类后**不进入结构化抽取**，仅记录类别日志，不抛异常（产品方案 3.3：过滤闲聊广告）
- 用户画像未配置（resume / intention 均为空）：**前置校验跳过打分**，提示填写 `user_resume` / `user_intention`，不调用 LLM、不产生错误码
- 分数越界（<0 或 >100）：**容错截断**到 [0,100] 并记录 WARN，不视为失败、不产生错误码

## 二、异常抛出原则

1. **业务异常主动抛自定义异常**：继承 `job_assistant/errors.py` 的 `JobAssistantError`，携带错误码，如 `ConfigError`、`ListenerError`
2. **底层原生异常包装后向上抛出**：例如 YAML 解析异常 `yaml.YAMLError` 包装为 `ConfigError` 后再抛出，禁止把原始堆栈直接暴露给使用方
3. **全局异常处理器统一捕获、统一返回结果**：程序入口（`main.py` 的 `__main__` 启动块）统一捕获 `JobAssistantError`，只输出一行带错误码的中文提示（如 `[CFG.LOAD.001] 配置文件不存在: ...`）后以**退出码 1**退出，不向使用方暴露原始堆栈；监听线程内部异常统一记录日志（`logger.exception`）并置停止标记，避免静默崩溃

## 三、常见异常案例

| 场景 | 异常类型 | 处理方式 |
| --- | --- | --- |
| 配置文件不存在 | `ConfigError` (CFG.LOAD.001) | 提示路径错误，退出程序 |
| YAML 语法错误 | `ConfigError` (CFG.LOAD.001) | 提示语法错误位置，退出程序 |
| 群号为负数/非数字 | `ConfigError` (CFG.LOAD.001) | 提示非法群号，退出程序 |
| user_resume / user_intention 类型非法 | `ConfigError` (CFG.LOAD.001) | 提示改为字符串（块文本），修正后重启程序 |
| NapCat 未启动/连接失败 | 可重试异常 | 记录 ERROR 日志，自动重连 |
| 未停止时重复 start() | `ListenerError` (LST.RUN.002) | 提示先停止再启动 |
| 收到非 JSON 报文 | 忽略（WARN 日志） | 不中断接收循环 |
| 图片下载失败（网络/超时/超限） | `ImageDownloadError` (MUL.DOWN.001) | 编排层标记失败分支，跳过该图，不阻断整体 |
| OCR 识别失败（依赖缺失/报错/超时） | `OcrError` (MUL.OCR.001) | 编排层标记失败分支；依赖缺失提示安装或关闭开关；超时调大 `ocr_timeout` |
| 网页抓取失败（超时/HTTP 错误） | `WebFetchError` (MUL.FETCH.001) | 编排层标记失败分支，跳过该链接，不阻断整体 |
| 网页/图片超过大小上限 | `PageTooLargeError` (MUL.FETCH.002) | 资源保护：跳过该条或调大上限 |
| 需登录 / JS 强渲染页面 | 策略性跳过（非异常） | 显式识别后不抓取正文，记录原因日志，不进 errors |
| LLM 服务不可达/超时/HTTP 错误 | `LLMCallError` (PAR.LLM.001) | `JobExtractor.parse` / `JobScorer.score` 捕获写入 `ParseResult.error` / `MatchResult.error`，标记该条，不阻断整体；检查 DeepSeek API Key 与 `llm.base_url` |
| LLM 输出无法解析为岗位 JSON | `LLMFormatError` (PAR.LLM.002) | 抽取阶段自动重试一次（`max_retries`），仍失败标记该条消息，不阻断整体 |
| LLM 打分输出无法解析 | `ScoreFormatError` (MAT.SCORE.001) | 打分阶段自动重试一次（`max_retries`），仍失败标记该岗位，不阻断整体 |
| 分数越界（<0 或 >100） | 容错截断（WARN） | 截断到 [0,100] 继续流程，不视为失败、不产生错误码 |
| 用户画像未配置 | 策略性跳过（非异常） | 前置校验跳过打分，提示填写 user_resume / user_intention，不调用 LLM |
| 闲聊广告/诈骗消息 | 策略性跳过（非异常） | 分类为 SPAM/FRAUD/OTHER 后不进入抽取，仅记录类别日志 |
| 岗位 JSON 归档失败（磁盘写失败） | `JobSaveError` (STO.SAVE.001) | `JobRepository.save_job` 捕获后标记返回（不入档），记录 WARN，不阻断后续岗位 |
| 日报写入失败（磁盘不可写） | `ReportError` (STO.REPORT.001) | main 记录 ERROR 后降级退出，不影响当日已归档岗位数据 |
| 打分失败岗位（error 非空） | 策略性跳过（非异常） | 不入档（无有效分数/理由），仅记录 WARN，不产生错误码 |
| 岗位重复（公司+岗位已存在） | 策略性跳过（非异常） | 去重保留首次记录，记录 INFO 日志，不重复落盘 |
| 公司/岗位缺失（【信息未提及】） | 策略性跳过去重（非异常） | 关键字段缺失无法可靠去重，直接归档不丢弃 |

## 四、实现约定

- `GENERAL.UNKNOWN.000` 为异常基类 `JobAssistantError` 的保留码，**禁止直接抛出**；新增业务异常必须继承基类、设置专属错误码并登记《错误码体系.md》对照总表
- 新增模块的异常类统一放在模块内或 `errors.py`，错误码登记到《错误码体系.md》
- 不允许捕获后静默吞掉异常且无日志；捕获必记录（ERROR/WARN 至少其一）
- 可重试操作必须设置重试上限或可配置间隔，防止死循环
- 多模态分支异常遵循**单条失败不阻断整体**：编排层捕获 `MultimodalError` 后写入 `MultimodalResult.errors` 并继续处理其余分支（见《常用工具类说明.md》）
- 模块四解析异常遵循**单条失败不阻断整体**：`JobExtractor.parse` 捕获 `LLMCallError`/`LLMFormatError` 后写入 `ParseResult.error`，由 main 记录 WARN 后继续处理下一条消息（见《常用工具类说明.md》）
- 模块五打分异常遵循**单条失败不阻断整体**：`JobScorer.score` 捕获 `LLMCallError`/`ScoreFormatError` 后写入 `MatchResult.error`，由 main 记录 WARN 后继续处理下一条消息（见《常用工具类说明.md》）
- 模块六归档异常遵循**单条失败不阻断整体**：`JobRepository.save_job` 捕获 `JobSaveError` 后标记返回（不入档），由 main 记录 WARN 后继续处理下一条岗位；日报生成失败（`ReportError`）由 main 记录 ERROR 后降级退出，不影响当日已归档数据（见《常用工具类说明.md》）
