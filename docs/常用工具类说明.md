> 适用项目：AI 求职信息智能筛选助手

## 二、各工具：作用、使用示例、注意事项

### 1. JobAssistantError（异常基类）

- **作用**：所有自定义异常的父类，自动携带错误码 `[{error_code}]` 前缀
- **使用示例**

```python
from job_assistant.errors import ConfigError, JobAssistantError

try:
    load_config("config.yaml")
except JobAssistantError as e:
    print(e)          # 输出: [CFG.LOAD.001] 配置文件不存在: ...
    print(e.error_code)  # CFG.LOAD.001
```

- **注意事项**：子类通过类属性 `error_code` 预置错误码；实例化时可显式覆盖；新增错误码需登记《错误码体系.md》

### 2. load_config（配置加载）

- **作用**：读取 `config.yaml`，校验后返回强类型 `AppConfig`（含 `napcat`、`monitor_group_ids`）
- **使用示例**

```python
from job_assistant.config.settings import load_config

cfg = load_config("job_assistant/config/config.yaml")
print(cfg.monitor_group_ids)      # [123456789, ...]
print(cfg.napcat.ws_url)          # ws://127.0.0.1:3001
```

- **注意事项**：文件缺失、坏 YAML、非法群号、非法 ws_url 均抛 `ConfigError`；空 `monitor_group_ids` 合法（表示不监听任何群）

### 3. filter_message（群白名单过滤）

- **作用**：对单条 OneBot v11 事件做白名单过滤，命中返回 `GroupMessage`，丢弃返回 `None`
- **使用示例**

```python
from job_assistant.listener.group_filter import filter_message

msg = filter_message(event_dict, [111, 222])   # event_dict 为 NapCat 推送的 JSON 反序列化结果
if msg is None:
    return          # 非监听群/非群消息/空白名单
print(msg.raw_text, msg.image_urls, msg.urls)   # 文本、图片地址、网页链接
```

- **注意事项**：只处理 `post_type=message` 且 `message_type=group` 的事件；`urls` 使用正则去重保序；图片地址供模块二 OCR 使用

### 4. GroupMessage（消息模型）

- **作用**：模块一的输出标准结构，模块二（多模态）的输入
- **字段**：`message_id / group_id / user_id / timestamp / raw_text / image_urls / urls / raw`
- **注意事项**：`raw` 保留原始事件便于扩展；新增字段需同步更新模块二消费逻辑

### 5. MultimodalProcessor（模块二编排入口）

- **作用**：对一条 `GroupMessage` 执行文本直传 / 图片 OCR / 网页抓取三分支，合并为完整文本，并归档原始素材到数据分目录
- **使用示例**

```python
from job_assistant.config.settings import AppConfig
from job_assistant.multimodal.processor import MultimodalProcessor

cfg = load_config("job_assistant/config/config.yaml")
processor = MultimodalProcessor(cfg.multimodal, cfg.data)

result = processor.process(msg)          # msg: GroupMessage
print(result.merged_text)                # 供模块四解析的完整文本
print(result.errors)                     # 失败分支标记（如 "[MUL.FETCH.001] ..."）
```

- **注意事项**：`ocr_engine` 参数支持注入（测试用替身）；单条分支失败不阻断整体，失败详情在 `result.errors`；数据目录自动创建

### 6. OCREngine（图片 OCR 引擎）

- **作用**：惰性加载 PaddleOCR 识别本地图片，兼容 2.x/3.x 返回结构；识别放入守护线程执行并设超时（默认 30 秒，可配 `ocr_timeout`）
- **使用示例**

```python
from job_assistant.multimodal.ocr_engine import OCREngine, download_image

path = download_image("https://example.com/poster.png", "data/image_raw")
text = OCREngine(lang="ch", timeout=30).recognize(path)   # 返回识别文本；无文字返回 ""
```

- **注意事项**：PaddleOCR 未安装时抛 `OcrError`（MUL.OCR.001），提示安装 `paddleocr paddlepaddle` 或关闭 `enable_ocr`；识别超时（`ocr_timeout`）同样抛 `OcrError`；超时线程为守护线程，随进程退出回收

### 7. fetch_web_page / fetch_web_text（网页抓取 + 正文提取）

- **作用**：抓取网页并提取正文（"标题：xxx + 可见文本"），设超时与大小上限；**显式识别需登录 / JS 强渲染页面并策略跳过**
- **使用示例**

```python
from job_assistant.multimodal.web_fetcher import fetch_web_page, fetch_web_text

text = fetch_web_text("https://example.com/job/1", timeout=10, max_bytes=1_048_576)

page = fetch_web_page("https://example.com/job/2", timeout=10, max_bytes=1_048_576)
if page.skip_reason:      # "需登录页面" / "JS 强渲染页面"
    print("跳过:", page.skip_reason)
else:
    print(page.text)
```

- **注意事项**：网络错误/HTTP 非 2xx/超时抛 `WebFetchError`（MUL.FETCH.001）；超过 `max_bytes` 抛 `PageTooLargeError`（MUL.FETCH.002）；登录/JS 渲染页为**策略性跳过**（返回空正文 + `skip_reason`），不抛异常

### 8. extract_urls / extract_web_text（链接提取与正文清洗）

- **作用**：`extract_urls` 从文本正则提取 http/https 链接（去重保序）；`extract_web_text` 从 HTML 提取标题与可见正文，跳过 script/style/head 等标签
- **注意事项**：链接提取为模块二 URL 分支第 1 步（产品方案 4.2）；空页面返回空串；HTML 结构异常记录 WARN 后按无正文处理，不抛异常

### 9. UserProfile / parse_profile（用户简历 & 求职意向，模块三）

- **作用**：`parse_profile` 从 YAML 根节点解析 `user_resume` / `user_intention` 为 `UserProfile`；`UserProfile.full_text()` 拼接「【用户简历】+【用户求职意向】」完整画像文本，作为模块五岗位匹配打分的输入。程序**不预置任何固定标签与权重**（产品方案 4.3）。
- **使用示例**

```python
from job_assistant.config.settings import load_config

cfg = load_config("job_assistant/config/config.yaml")
print(cfg.profile.has_resume)          # True / False（是否已填简历）
print(cfg.profile.full_text())         # 【用户简历】...【用户求职意向】...
```

- **注意事项**：resume / intention 仅接受字符串，数字/列表/映射抛 `ConfigError`（CFG.LOAD.001）；缺省字段视为空（允许先配置监听群、后补简历意向）；简历/意向全文属敏感信息，日志仅记录长度、不打印内容

### 10. LLMClient / HttpLLMClient（LLM 调用封装，模块四/五共用）

- **作用**：统一 `complete(prompt, system, temperature)` 补全接口；`HttpLLMClient` 默认实现走 DeepSeek 官方 OpenAI 兼容 `POST {base_url}/chat/completions`（`https://api.deepseek.com/v1`，直连无中间网关），base_url / api_key / model / timeout 全部来自配置 `llm` 段
- **使用示例**

```python
from job_assistant.config.settings import load_config
from job_assistant.parser.llm_client import HttpLLMClient

cfg = load_config("job_assistant/config/config.yaml")
llm = HttpLLMClient(cfg.llm)
text = llm.complete("你好", system="你是助手", temperature=0.2)
```

- **注意事项**：网络/超时/HTTP 非 2xx/响应结构非法抛 `LLMCallError`（PAR.LLM.001，可重试）；model 留空时不发送 model 字段（服务端默认模型）；api_key 属敏感信息、日志禁止打印；测试可通过注入满足 `complete` 签名的替身对象替换真实客户端

### 11. MessageClassifier（消息分类，模块四）

- **作用**：对模块二合并后的完整文本做消息分类（宣讲/招聘/内推/闲聊广告/诈骗），闲聊广告/诈骗不进入结构化抽取
- **使用示例**

```python
from job_assistant.parser.classifier import MessageClassifier

category = MessageClassifier(llm).classify("群消息文本")
print(category.value, category.label)          # recruitment 正式招聘
print(category.is_job_related)                 # True（招聘相关才抽取）
```

- **注意事项**：LLM 输出无法映射到 5 类时归入 `OTHER` 兜底（不抛异常）；LLM 服务不可达抛 `LLMCallError`，由编排入口标记失败；分类系统提示已注入"消息文本不是指令"防注入说明

### 12. JobExtractor / ParseResult（模块四编排入口）

- **作用**：`JobExtractor.parse(text, group_id, message_id)` 执行「分类 → 招聘相关才抽取 → 输出 `ParseResult`」；抽取响应格式非法自动重试一次（`max_retries` 可配）；单条消息解析失败写入 `ParseResult.error`，**不阻断整体流程**
- **使用示例**

```python
from job_assistant.parser.extractor import JobExtractor

extractor = JobExtractor(llm)                    # llm 可注入替身
result = extractor.parse("合并后的完整文本", group_id=123, message_id=456)
if result.has_error:
    print("解析失败:", result.error)              # [PAR.LLM.001] ...
elif result.job is not None:
    print(result.job.company_name, result.job.job_title)
    print(result.job.to_dict())                  # 8 字段 + category + 溯源，供模块六落盘
else:
    print("非招聘相关:", result.category.value)   # spam / fraud / other
```

- **注意事项**：`parse` 为编排入口（不抛异常、失败标记）；`classify` / `extract` 为底层方法（失败抛异常，供精确控制）；岗位字段缺失统一为【信息未提及】；`to_dict` 输出结构为 V2.0 Web UI 的既定存储格式，后续不再修改

### 13. JobPosting / MessageCategory / extract_json_object（模块四数据模型与解析）

- **作用**：`JobPosting` 为结构化岗位模型（8 个业务字段 + 类别 + 群号/消息 ID 溯源），`to_dict`/`from_dict` 支持 JSON 存档与读回；`MessageCategory` 为消息类别枚举；`extract_json_object` 从 LLM 输出提取 JSON 对象（支持纯 JSON / markdown 代码块 / 文本内嵌）
- **注意事项**：字段缺失统一标【信息未提及】，不强行补全（产品方案 6.4 容错）；`from_dict` 容忍缺失字段与未知字段（兼容未来扩展）；`normalize_category` 支持枚举值、值字符串、中文字面量、未知值兜底 OTHER

### 14. JobScorer / MatchResult（岗位匹配打分，模块五）

- **作用**：`JobScorer.score(job)` 对单个结构化岗位执行 LLM 动态打分（输入岗位 + 用户简历 + 求职意向），输出 `MatchResult`（0~100 分 + 理由 + 阈值过滤标记）。**取消 V1.0 固定权重，完全由用户画像驱动**（产品方案 4.5）
- **使用示例**

```python
from job_assistant.config.settings import load_config
from job_assistant.matcher.scorer import JobScorer
from job_assistant.parser.llm_client import HttpLLMClient

cfg = load_config("job_assistant/config/config.yaml")
scorer = JobScorer(HttpLLMClient(cfg.llm), cfg.profile, threshold=cfg.recommend_score_threshold)

match = scorer.score(job)                  # job: JobPosting（模块四输出）
if match.has_error:
    print("打分失败:", match.error)         # [PAR.LLM.001] / [MAT.SCORE.001] / 画像未配置提示
elif match.is_recommended:
    print(match.score, match.reason)       # 推荐岗位（≥ 阈值）：控制台完整输出 + 写日报
else:
    print(match.score)                     # 仅存档岗位（< 阈值）：极简日志 + JSON 存档
```

- **注意事项**：`score()` 为编排入口（不抛异常、失败标记）；打分响应格式非法自动重试一次（`max_retries`）；分数越界容错截断到 [0,100]（WARN）；用户画像未配置时前置校验跳过打分、不调用 LLM；`MatchResult.is_recommended` = 打分成功且 score ≥ threshold

### 15. rank_by_score / recommend_score_threshold（排序与阈值，模块五）

- **作用**：`rank_by_score` 按匹配分数降序稳定排序（同分保持原顺序、失败项排末尾），供模块六日报按分数降序展示；`recommend_score_threshold` 为 YAML 配置项（默认 80），划分推荐岗位（≥ 阈值）与仅存档岗位（< 阈值）
- **注意事项**：阈值仅接受 0~100 的 YAML 整数，浮点/字符串/越界均抛 `ConfigError`（拒绝静默截断）；排序不修改入参列表

### 16. JobRepository（岗位归档仓储，模块六）

- **作用**：基于「公司名称 + 岗位名称」去重（重复保留首次记录），把模块五打分结果全量 JSON 永久存入 `./data/jobs`；存档记录 = `JobPosting.to_dict()` 11 字段 + 打分字段（score / reason / threshold / recommended）+ 归档时间戳（recorded_at），字段只增不减，兼容 V2.0 Web UI 读取
- **使用示例**

```python
from job_assistant.config.settings import load_config
from job_assistant.storage.repository import JobRepository

cfg = load_config("job_assistant/config/config.yaml")
repo = JobRepository(cfg.data.paths["jobs"])          # 目录不存在时自动创建

ok = repo.save_job(match)                              # match: MatchResult（模块五输出）
# ok=True 新写入；False=去重跳过 / 打分失败不入档 / 归档失败
records = repo.load_by_date(date.today())              # 当日新增岗位（日报输入）
recommended = repo.load_recommended(date.today())      # 当日推荐岗位（仅 ≥ 阈值）
all_records = repo.load_all()                          # 全部历史岗位
```

- **注意事项**：`save_job` 为编排入口（不抛异常、失败标记返回）；打分失败岗位不入档（WARN）；公司/岗位缺失（【信息未提及】）时无法可靠去重，直接归档不丢弃；去重索引启动时扫描历史存档重建（个人规模 N 可接受）；文件名 `{日期}_g{群}_m{消息}_{公司}_{岗位}.json`（非法字符清洗，日期前缀供日报按当日聚合）；**去重键已归一化（v0.7.0）**：公司名走 `normalize_company_name`（华为半导体业务部/华为海思→华为，去集团/股份/科技等后缀）、岗位名走 `normalize_job_title`（去 J 编号/括号/【信息未提及】）、泛校招（软件开发工程师/校招/秋招等）归 `\x1fgeneric` 同公司只留一条

### 18. research_company / enrich_missing_fields（公司风评检索 + 残缺补全，业务插件层）

- **作用**：`research_company(company, job_title)` 检索公司外部资料（员工风评 / WLB / 舆情 / 经营简介）供打分参考；`enrich_missing_fields` 对缺公司名/岗位名的残缺岗位自动补全缺失字段
- **使用示例**

```python
from job_assistant.research.company_research import research_company, enrich_missing_fields

ext = research_company("普渡机器人", job_title="后端开发工程师", timeout=10.0, max_chars=3000)
print(len(ext))                 # 多源检索 + 牛客浏览器兜底的截断资料串（供打分提示词【公司外部检索资料】段）

job = JobPosting(company_name="普渡机器人", job_title=MISSING, ...)   # 残缺岗位
enriched, src_text = enrich_missing_fields(job, llm=llm, timeout=10.0)
print(enriched.job_title)       # 补全后岗位名（如"后端开发工程师"）
```

- **注意事项**：
  - 检索链路（v0.7.0）：多路检索词（`"{公司}" 怎么样/加班/工作体验/评价` + `site:nowcoder.com` + 小红书语境词）→ 多源搜索（Bing/神马/百度，全部检索词都执行）→ 牛客页 HTTP 抓正文 → **牛客内容不被搜索引擎索引时自动 Playwright 渲染牛客搜索页兜底**（`_browser_nowcoder`，同公司缓存 `_NOWCODER_CACHE` 只查一次、上限 200 条）
  - 平台标记：`_platform_of` 命中 nowcoder.com / xiaohongshu.com 的来源优先展示；**小红书搜索页为登录墙**（无头浏览器被"手机号登录"拦截），目前只能尽力命中搜索引擎摘要
  - 全部检索失败自动降级：返回空串，打分侧标注「未自动联网核验，WLB 需人工自查」，不阻断
  - 补全抽取只依据检索资料下结论，不得编造；LLM 输出「信息未提及/未知/无」等变体统一归一为【信息未提及】；补全失败保持残缺标记
  - 依赖 Playwright（仅 anaconda Python 3.11 环境可用）；HTTP 通道失败才降级浏览器，控制开销

### 19. browser_fetch_texts / browser_fetch_links（Playwright 无头浏览器渲染）

- **作用**：HTTP 抓不到（JS 强渲染 / 反爬）时用无头浏览器渲染页面——`browser_fetch_texts` 渲染后提取正文文本，`browser_fetch_links` 渲染后提取校招入口链接（campus / career / recruit / zhiye / job / jobs / join / talent）
- **使用示例**

```python
from job_assistant.research.browser_fetch import browser_fetch_texts, browser_fetch_links

text = browser_fetch_texts(["https://pudutech.zhiye.com/campus"], max_chars=1500, wait_ms=4500)
links = browser_fetch_links(["https://www.pudutech.com/zh-CN/company"], max_chars=800, wait_ms=4000)
```

- **注意事项**：必须 `playwright` + Chromium 已安装（`python -m playwright install chromium`）；同步 API 仅在 anaconda Python 3.11 可用（系统 Python 3.14 沙箱运行时不可用）；页面渲染失败返回空串不抛异常；单页超时 `timeout_ms` 控制

### 20. normalize_company_name / normalize_job_title / dedupe_jobs / recompute_recommended（去重与阈值重算，模块六增强）

- **作用**：`normalize_company_name` 公司名归一化（别名表 + 去后缀）、`normalize_job_title` 岗位名归一化（去噪音）、`dedupe_jobs` 全量自动去重（保留最优、重复备份）、`recompute_recommended` 按最新阈值全量重算推荐标记
- **使用示例**

```python
from job_assistant.storage.repository import dedupe_jobs, recompute_recommended

print(dedupe_jobs("data/jobs"))
# {'scanned': 36, 'groups': 0, 'kept': 24, 'moved': 0, 'backup_dir': 'jobs_dedup_backup_20260920_042411'}
print(recompute_recommended("data/jobs", threshold=50))
# {'scanned': 36, 'updated': 0, 'failed': 0}
```

- **注意事项**：`dedupe_jobs` 保留最优 = 推荐优先 → 分数高 → 字段完整度（7 字段）→ 文件名新；重复文件移入 `data/jobs_dedup_backup_<时间戳>/` **不删除**；缺公司名/损坏文件不参与去重；`recompute_recommended` 只改 recommended/threshold 字段不改分数，幂等可重复；两者由 `main.py` 启动钩子自动触发，`server.py save_config` 保存阈值时也会重算

### 17. DailyReport / ReportResult（每日日报生成器，模块六）

- **作用**：读取当日新增推荐岗位（按存档时 `recommended` 标记），按匹配分数降序稳定排序，生成 Markdown 日报（附带分数、打分理由、信息来源、消息来源溯源）写入 `./data/report/{YYYY-MM-DD}.md`；低分岗位不写入日报
- **使用示例**

```python
from datetime import date
from job_assistant.storage.report import DailyReport

report = DailyReport(cfg.data.paths["report"])
result = report.generate(repo, threshold=cfg.recommend_score_threshold)  # repo: JobRepository
print(result.path.name)          # 2026-09-18.md
print(result.recommended_count)  # 推荐岗位数
print(result.archived_count)     # 当日全量存档数
print(result.markdown)           # 完整 Markdown 正文
```

- **注意事项**：`generate` 为编排入口（读取→排序→渲染→落盘一步完成）；写入失败抛 `ReportError`（STO.REPORT.001），由 main 记录 ERROR 后降级退出；空日报兜底（0 推荐仍落盘并提示）；同一日多次运行覆盖为最新日报；排序与模块五 `rank_by_score` 语义一致（分数降序、同分保持归档顺序）

## 三、扩展约定

- 后续模块工具类（归档仓储、日报生成器等）按模块归位，并在本表登记
- 工具类必须附带精简注释与使用示例，重要设计决策同步写入对应 docs 文档
- 模块二异常（`MultimodalError` 及子类）遵循**单条失败不阻断整体**，统一由编排层捕获并写入 `MultimodalResult.errors`
- 模块四异常（`ParserError` 及子类）遵循**单条失败不阻断整体**，统一由编排入口捕获并写入 `ParseResult.error`
- 模块五异常（`MatchError` 及子类）遵循**单条失败不阻断整体**，统一由编排入口捕获并写入 `MatchResult.error`；LLM 调用失败复用 `LLMCallError`（PAR.LLM.001，LLM 客户端层模块四/五共用）
- 模块六异常（`StorageError` 及子类）遵循**单条失败不阻断整体**：`JobRepository.save_job` 捕获 `JobSaveError` 后标记返回（不入档）；日报生成失败（`ReportError`）由 main 记录 ERROR 后降级退出，不影响当日已归档数据
