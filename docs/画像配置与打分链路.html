画像配置如何驱动岗位打分

AI 求职信息智能筛选助手 · config.yaml 填法示意（纯 LLM 动态打分，无固定权重，画像文本即打分标准）

① config.yaml 输入

user_resume（简历全文）
教育 / 项目 / 技能 / 证书 → 提供“能力证据”，约 1185 字
user_intention（求职意向）
岗位 / 技术栈 / 城市 / 行业 / 硬排 / 偏好 / 薪资 → 提供“筛选标准”，约 562 字
recommend_score_threshold
当前 50：≥50 进日报推荐，<50 仅存档；修改后 Web 保存或重启自动全量重算全部岗位
→

② 模块五 LLM 打分（三个维度）

1
技能匹配度岗位要求 × 简历能力（技术栈、项目经验、学历）
2
意向匹配度地点 / 行业 / 岗位方向；命中硬性排除 → 直接 ≤30 分
3
公司外部核验联网检索 WLB / 规模 / 员工风评，只影响风险提示与偏好加分，不改变岗位本身匹配度
→

③ 输出决策

score ≥ 50
推荐岗位：控制台完整输出、写入每日日报（阈值修改自动全量重算）
score < 50
仅存档：结构化 JSON 保留，不进推荐/日报

user_intention 关键写法与作用（本次已按此优化）

意向里的写法为什么这么写
主栈Java / Spring Boot / MySQL / Redis / RocketMQ
无实战Python / Go / Kafka（岗位要求时扣分）
方向AI 辅助开发 / AI Agent 应用开发可接受，但核心语言须以 Java 主栈为主		分清“已掌握”和“无实战”：Go/Python 作为岗位核心语言时因无实战经验扣分，防止 LLM 误当成成熟经验；AI 方向岗位可以投，但不豁免技术栈匹配要求
硬性排除：销售 / 客服 / 倒班 / 教培，并注明“命中应低于 30 分”对齐打分语义（0~30=命中硬排），让“排除”真正变成硬条件
小而美外企 = 外资独资/控股或跨国公司在华机构，≤1000 人优先把模糊的“外企”量化，配合公司外部检索才能被 LLM 可靠判断
WLB = 双休、无强制加班 / 996 / 大小周检索到的员工风评（加班、双休与否）可以直接对应，减少臆测
薪资底线：税前年薪（base+奖金）≥ 10 万原文“年报”系笔误已改“年薪”；未注明薪资的岗位不扣分，投递前人工确认，避免误杀信息不全的岗位
四城“一视同仁”；行业“均可（只看岗位本身）”明示不因城市/行业额外加权，防止 LLM 自行猜测西安优先或行业偏好
示意说明：打分维度和阈值语义来自项目 scorer.py / 产品方案 4.5；画像文本为当前写入 config.yaml 的版本（user_resume 1185 字、user_intention 562 字、阈值 50）。阈值修改后 Web 保存或重启程序即自动全量重算推荐标记（v0.7.0）；残缺岗位打分前自动浏览器补全、打分前自动检索公司风评/WLB（牛客等）。
