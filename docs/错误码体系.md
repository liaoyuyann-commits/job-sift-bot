# 错误码体系

> 适用项目：AI 求职信息智能筛选助手
> 维护规则：新增错误码必须在本文件登记，并与代码中的异常类保持一一对应。
> 文档索引：返回 [README.md](../README.md) 文档索引 ｜ 配套规范：[异常处理指南.md](异常处理指南.md)、[日志规范.md](日志规范.md)

## 一、错误码设计格式

采用 **`{业务域}.{模块}.{三位数字}`** 格式，数字编码，便于检索与日志聚合。

```
CFG.LOAD.001
│    │    └── 三位数字：同域内递增编号，001 起
│    └── 模块缩写：LOAD=加载/解析, VALID=校验, CONN=连接, RUN=运行, DOWN=下载, FETCH=抓取, OCR=识别, PARSE=解析, SAVE=归档, REPORT=日报
└── 业务域缩写：CFG=配置, LST=监听, MUL=多模态, PAR=解析, MAT=匹配, STO=存储
```

> **基类保留码**：`GENERAL.UNKNOWN.000` 是 `job_assistant/errors.py` 中 `JobAssistantError` 基类的默认码，仅作未设置错误码时的兜底，**禁止在业务代码中直接抛出**；所有具体异常必须在子类用 `error_code` 类属性设置下列专属错误码。

## 二、错误分类（按错误性质）

| 分类 | 说明 | 处理策略 |
| --- | --- | --- |
| 参数/配置错误 | 配置文件缺失、格式非法、字段校验失败 | 不可重试，修正配置后重启 |
| 连接异常 | NapCat 连接失败、断线；图片下载/网页抓取网络错误 | 可重试，按重连间隔自动恢复或由编排层标记后跳过 |
| 业务异常 | 重复启动、OCR 依赖缺失、页面超过大小上限等运行期冲突 | 需人工介入或调整调用方式 |
| 系统内部异常 | 未预期异常 | 记录完整堆栈，定位修复 |

> 模块二补充说明：多模态单条分支失败（下载/OCR/抓取）由编排层捕获并记录到 `MultimodalResult.errors`，**不阻断整体流程**（见《异常处理指南.md》）。

## 三、错误码明细

### 异常类 ↔ 错误码对照总表（与 `job_assistant/errors.py` 一一对应）

| 异常类 | 错误码 | 所属域 | 可重试 | 抛出/处理位置 |
| --- | --- | --- | --- | --- |
| `JobAssistantError`（基类） | GENERAL.UNKNOWN.000 | 保留 | — | 仅兜底保留码，禁止直接抛出 |
| `ConfigError` | CFG.LOAD.001 | CFG | 否 | 配置加载/校验失败；main 入口统一捕获，退出码 1 |
| `ListenerError` | LST.RUN.001 | LST | 否 | 监听模块兜底异常（预留） |
| `ListenerError`（实例化覆盖） | LST.RUN.002 | LST | 否 | 重复启动监听器；先 stop() 再 start() |
| `MultimodalError` | MUL.PARSE.001 | MUL | 否 | 多模态处理兜底异常（预留） |
| `ImageDownloadError` | MUL.DOWN.001 | MUL | 是 | 图片下载失败；编排层标记分支，不阻断整体 |
| `OcrError` | MUL.OCR.001 | MUL | 否 | OCR 依赖缺失/识别报错/超时；标记分支不阻断 |
| `WebFetchError` | MUL.FETCH.001 | MUL | 是 | 网页抓取失败；编排层标记分支，不阻断整体 |
| `PageTooLargeError` | MUL.FETCH.002 | MUL | 否 | 页面/图片超大小上限；资源保护，跳过该条 |
| `ParserError` | PAR.RUN.001 | PAR | 否 | 解析模块兜底异常（预留） |
| `LLMCallError` | PAR.LLM.001 | PAR | 是 | LLM 网络/超时/HTTP/结构非法；模块四/五共用，单条标记不阻断 |
| `LLMFormatError` | PAR.LLM.002 | PAR | 重试一次 | 抽取响应格式非法；重试后仍失败标记该条 |
| `MatchError` | MAT.RUN.001 | MAT | 否 | 打分模块兜底异常（预留） |
| `ScoreFormatError` | MAT.SCORE.001 | MAT | 重试一次 | 打分响应格式非法；重试后仍失败标记该岗位 |
| `StorageError` | STO.RUN.001 | STO | 否 | 归档/日报兜底异常（预留） |
| `JobSaveError` | STO.SAVE.001 | STO | 否 | 单条岗位归档失败；save_job 捕获标记返回，不阻断 |
| `ReportError` | STO.REPORT.001 | STO | 否 | 日报写入失败；main 记录 ERROR 后降级退出 |

> 约定：兜底类错误码（`*.RUN.001` / `MUL.PARSE.001`）为预留码，用于未归类异常；已知业务场景必须使用具体错误码，不得用兜底码替代。

### CFG 域（配置）

| 错误码 | 提示文案 | 触发场景 | 前端/使用处理建议 |
| --- | --- | --- | --- |
| CFG.LOAD.001 | 配置加载/校验失败 | 配置文件缺失、YAML 语法错误、群号非法、ws_url 协议非法、user_resume/user_intention 类型非法（非字符串） | 检查 config.yaml 内容与路径，修正后重启程序 |

### LST 域（监听模块）

| 错误码 | 提示文案 | 触发场景 | 前端/使用处理建议 |
| --- | --- | --- | --- |
| LST.RUN.001 | 监听器运行异常 | 监听线程内部未预期异常（预留） | 查看日志定位，必要时重启 |
| LST.RUN.002 | 监听器已在运行中 | 未停止监听器时重复调用 start() | 先 stop() 再 start() |

> 连接失败（LST 域）当前不抛错误码，由 `NapCatListener` 内部记录 ERROR 日志并按 `reconnect_interval` 自动重连，属于**可重试异常**（见《异常处理指南.md》）。

### MUL 域（多模态模块）

| 错误码 | 提示文案 | 触发场景 | 前端/使用处理建议 |
| --- | --- | --- | --- |
| MUL.DOWN.001 | 图片下载失败 | 网络错误、HTTP 非 2xx、超时、超过大小上限 | 可重试；由编排层标记失败分支，不阻断整体 |
| MUL.OCR.001 | OCR 识别失败 | PaddleOCR 未安装、初始化/识别报错、识别超时（`ocr_timeout`） | 安装 `paddleocr paddlepaddle`，或关闭 `enable_ocr` 开关 / 调大 `ocr_timeout` |
| MUL.FETCH.001 | 网页抓取失败 | 连接超时、HTTP 错误、网络不可达 | 可重试；由编排层标记失败分支，不阻断整体 |
| MUL.FETCH.002 | 页面超过大小上限 | 响应体超过 `web_max_bytes` / `image_max_bytes` | 属资源保护，跳过该条或调大上限 |
| MUL.PARSE.001 | 多模态处理兜底异常 | 未归类的多模态处理异常（预留） | 查看日志定位 |

### PAR 域（AI 解析模块）

| 错误码 | 提示文案 | 触发场景 | 前端/使用处理建议 |
| --- | --- | --- | --- |
| PAR.LLM.001 | LLM 调用失败 | LLM 服务不可达（网络/超时）、HTTP 非 2xx、响应非 JSON 或缺 choices 字段 | 可重试：检查 DeepSeek API Key 是否有效、网络连通性与 `llm.base_url`；由编排入口标记该条消息解析失败，不阻断整体 |
| PAR.LLM.002 | LLM 响应格式非法 | LLM 输出无法解析为岗位 JSON（非 JSON / 字段结构错误） | 抽取阶段自动重试一次（`max_retries`）；仍失败标记该条消息，不阻断整体 |
| PAR.RUN.001 | 解析模块兜底异常 | 未归类的解析模块异常（预留） | 查看日志定位 |

> 模块四补充说明：单条消息解析失败（分类/抽取）由编排入口 `JobExtractor.parse` 捕获并写入 `ParseResult.error`，**不阻断后续消息处理**（见《异常处理指南.md》）；闲聊广告/诈骗消息不进入抽取，不产生错误码。

### MAT 域（岗位匹配打分模块）

| 错误码 | 提示文案 | 触发场景 | 前端/使用处理建议 |
| --- | --- | --- | --- |
| MAT.SCORE.001 | LLM 打分响应格式非法 | LLM 输出无法解析为 {score, reason}（非 JSON / 缺 score / score 为布尔） | 打分阶段自动重试一次（`max_retries`）；仍失败标记该岗位，不阻断整体 |
| MAT.RUN.001 | 打分模块兜底异常 | 未归类的打分模块异常（预留） | 查看日志定位 |

> 共用说明：**PAR.LLM.001（`LLMCallError`）为 LLM 客户端层通用错误**，模块四（解析）与模块五（打分）复用同一 `HttpLLMClient`，调用失败均抛该码，由各自编排入口捕获并标记单条失败。
> 模块五补充说明：分数越界（<0 或 >100）按容错**截断**到 [0,100] 并记录 WARN，不产生错误码；用户画像未配置为业务前置条件，打分跳过并提示填写 `user_resume` / `user_intention`，不产生错误码。

### STO 域（本地归档与日报模块）

| 错误码 | 提示文案 | 触发场景 | 前端/使用处理建议 |
| --- | --- | --- | --- |
| STO.SAVE.001 | 岗位 JSON 归档失败 | 磁盘写入失败、序列化异常（`JobSaveError`） | 检查 `data.jobs` 目录可写与磁盘空间；由 `JobRepository.save_job` 捕获标记返回，单条不阻断整体 |
| STO.REPORT.001 | 日报生成失败 | 日报 Markdown 写入失败（磁盘不可写等，`ReportError`） | 检查 `data.report` 目录可写与磁盘空间；由 main 记录 ERROR 后降级退出，不影响当日已归档岗位 |
| STO.RUN.001 | 存储模块兜底异常 | 未归类的归档/日报异常（预留） | 查看日志定位 |

> 模块六补充说明：单条岗位归档失败由编排入口 `JobRepository.save_job` 捕获并标记返回（不入档、不抛异常），**不阻断后续岗位处理**（见《异常处理指南.md》）；打分失败岗位（`MatchResult.error` 非空）不入档且不产生错误码，仅记录 WARN；去重跳过（公司+岗位已存在）与关键字段缺失不去重均为业务规则，不产生错误码。

## 四、登记规范

1. 新增异常类必须继承 `job_assistant/errors.py` 中的 `JobAssistantError` 并设置 `error_code`
2. 错误码三位数字域内递增，不重复使用
3. 本表同步登记：编码、提示文案、触发场景、处理建议
4. `GENERAL.UNKNOWN.000` 为基类保留码，禁止直接抛出；已知业务场景禁止用兜底码（`*.RUN.001` / `MUL.PARSE.001`）替代具体错误码
5. 错误码的抛出层级与捕获方式须与《异常处理指南.md》保持一致：单条失败不阻断（MUL/PAR/MAT/STO.SAVE）、日报失败降级（STO.REPORT）、配置失败由 main 入口统一捕获后退出（CFG）
